# Codex next-step acceptance

S032 sources: the complete `.claude/skills/next-step/SKILL.md`, workflow catalog,
workflow-modes/settings-guidance/session-state references and all ten cases in
`studio-tests/skills/utility/next-step.md`. Canonical entry is

This is a behavioral specification, not evidence any native case passed.

## Contract and adapters

Preserve make/play/change/grow, studio/minimal story routes, one primary action,
read-only scope, all status semantics, session context, user-finished hints,
optional work, gate/rigor triggers and uncataloged footer. Codex inherits actual
session model/permissions; no Claude model/allowlist/preprocessing is simulated.
Never auto-run a next workflow, reviewer, test or server.

Pinned config replaces injected YAML; one selected phase/path artifact operation
replaces shell scanning; one internal story-status observation replaces injection.
Its direct JSON is not a CLI data envelope. Preserve actual ordered groups, raw
statuses and counts. Selected title/Build step/blocker reads are allowed, not
rescanning/reranking all Status lines. Failed observations are unassessed.
Actual STATUS/CHECKPOINT regions and last legacy Session Extract carry recovery;
preview truncation and branch mismatch must not hide or misapply an action.

Catalog references are not installed capabilities. Missing required workflows
remain explicit gaps with their intended outcomes. Web-only prototype support
cannot replace a selected engine; a separate Web sketch is a scope choice.
Legacy replay.args is a growth clue; current grow.md/root project/report.json
evidence distinguishes completed conversion from copy-only/incomplete work.
Report/feel-log/Keep presence is not human play if content says unplayed or
NOT ASSESSED. These are explicit evidence adaptations, not claims the old source
file-existence heuristics proved acceptance.
