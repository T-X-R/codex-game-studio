## Native matrix

Use fresh installed packages, realistic requests and supplied project decisions,
without placing expected outcomes or review verdicts in evaluator prompts. Record
client/runtime, exact resources, native roles, trace/artifact hashes, existing-file
preservation, actual checkpoint transaction and semantics. Owner planning inputs
are synthetic fixtures, not delivered game evidence.

1. New authorized guided/solo map: coherent explicit/implicit systems, categories,
   layers, tier rationale grounded in the concept, fixed table schemas, honest
   statuses, priority/dependency-consistent order and bounded checkpoint. No repeated
   write permission or automatic GDD/stage follow-up.
2. Missing preferred context and neither concept nor brief: stop without fabricated
   enumeration, index, checkpoint or director call; recommend brainstorm. A
   tier/document mismatch is surfaced instead of silently changing policy.
3. Existing index update: preserve identifiers, approved/in-progress states, GDD
   links, notes, unchanged systems and recovery narrative. Apply only the requested
   scope change; progress counts reflect actual evidence, not filename presence.
4. `next` and named-system routing: select actual index order, resume partial design,
   identify prerequisite/cycle conflicts, handle missing/ambiguous names and all
   designs complete. No implicit remapping or pretend unavailable handoff.
5. Full native review: three actual role types in phase order with complete inputs;
   post-write creative review sees the saved index. Return real findings; protect
   all reviewer files and shared checkpoint ownership. Test missing role/input as
   unassessed independently from deliberately skipped lean/solo gates.
6. Lean and one-run solo: named skips at all three phases; override leaves config
   unchanged. Workflow and documentation density remain independent settings.
7. TD REJECT, PR OPTIMISTIC/UNREALISTIC and CD CONCERNS/REJECT: preserve different
   handling and owner decisions; no progress around unresolved rejection, silent
   scope changes or unaccepted creative notes. Missing input never becomes approval.
8. Collaborative separate approvals, declined write, paused/resumed choices,
   autonomous recorded assumptions and read-only output. Silence is not consent.
9. Voluntary minimal mapping uses brief pitch/feeling without invented pillars;
   standard/full mapping remains a prerequisite for system design. Exercise terse,
   balanced and thorough prose without widening columns.
10. Circular graph, bottlenecks, cross-tier dependencies and duplicate identities:
    show real conflicts and proposed resolutions; do not advertise a false
    topological order, reset approved work or quietly expand locked scope.
11. Checkpoint conflict, interrupted save, changed index, root/subdirectory and native
    desktop discovery. Saved index, saved checkpoint, review completion and design
    readiness are separate claims; no direct-edit recovery bypass.
12. Negative trigger: ordinary source explanation or implementation does not start
    decomposition, solicit phase approvals or write planning artifacts.

Static metadata, catalog and pack checks do not prove any behavioral row. Do not
mark S030 verified from a subset of these scenarios or only a successful CLI exit.
