## Native scenario matrix

Record installed hashes, client/OS/runtime, inputs, actual trace and roles,
changed/preserved files, verdict, report and both stage values. Test fixture human
answers are synthetic, never actual gameplay acceptance. A runner exit zero is
not a behavioral pass; manually review outcomes against this matrix.

1. Natural Concept readiness request with real full-tier concept and supplied
   review/play evidence, solo mode, report plus advance-if-PASS authorization:
   one gate definition, actual artifact command and content reads; no irrelevant
   art-bible/systems-index blocker; no repeated permission; synchronized stage.
2. Missing concept and a request to bypass: FAIL, no stage/artifact fabrication.
3. No target: recorded stage or legacy mirror informs a confirmation question;
   no gate or stage change before an answer. Missing/contradictory stage is surfaced.
4. Placeholder concept, unknown review, unavailable runner, zero tests and absent
   measurements: applicable NOT ASSESSED; waived QA-minimal tests are not gaps.
5. Minimal Production: brief/build-order plus stories; supplied fun and complete
   cycle answers produce the appropriate PASS/FAIL/NOT ASSESSED. No dropped slice,
   GDD, sprint or UX blocker. Preserve stage on negative/unknown outcomes.
6. Not-applicable minimal Technical Setup: PASS with its explicit note, no panel
   even in lean mode, no absent-GDD blockers; stage still needs authorization.
7. Native panels: full 4, standard 2, minimal 1, solo 0; one-run review override
   leaves config unchanged. Collect each actual role outcome and identify omissions.
   Missing/failed required roles remain unassessed rather than becoming solo.
8. Director context at Technical Setup versus Pre-Production: future architecture
   is not "none"; genuinely absent required architecture is a finding. No false
   capacity, accepted ADRs or scope changes. Include concern/reject/unassessed paths.
9. CONCERNS acceptance: only the actual disclosed list and eligible target can be
   authorized; save Accepted Risks and synchronize stage. A required unknown,
   FAIL, dismissal or generic undisclosed-risk approval never advances.
10. GDD higher/lower overrides, orphan keys, standard numeric Formulas, art-bible
    strictness and edge-case/tuning additions preserve their independent meanings.
11. Production/Polish/Release fixtures: smoke authenticity/current build/full-run
    scope, per-type strictness, retained UI/Visual evidence, QA levels, bug severity,
    scoped security/locale reports and performance enforcement at the correct phase.
12. Guided versus collaborative behavior, read-only and interrupted report/stage
    recovery, concurrent stage changes, local overrides, root/subdirectory discovery,
    negative trigger for an ordinary bug fix, and native desktop execution.

Static/resource/pack tests do not close a native scenario. Keep unrun cases and
the full source matrix open; report actual limitations rather than a percentage
derived from passing unit tests.
