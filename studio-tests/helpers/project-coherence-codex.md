# project-coherence: portable observation contract

Migration source: `.claude/scripts/project-coherence.sh`, especially its six numbered checks; caller contract: `.claude/skills/setup-engine/references/8-verify.md` section 8.5. Upstream attribution remains in the repository. This helper is an internal package resource, not a new public CLI command, game-quality gate, or engine acceptance test.

## Invocation and result

Resolve `studio/scripts/project-coherence.mjs` with the project's pinned runtime resource-path command. Run the returned path with:

```text
node <resolved-path> --project <game-root> [--probe] [--timeout <milliseconds>] [--text]
```

The TypeScript API is `inspectProjectCoherence(root, {probe?, timeoutMs?})`; `formatProjectCoherence(result)` formats the same observations. Default is JSON; text is human-readable source-shaped output, not byte-identical Bash output. No environment variable selects another project. Duplicate/unknown flags and missing arguments fail with exit 2. Timeout is an integer from 100 through 60000, default 10000 ms. Help exits 0.

A completed observation returns `exitCode: 0`, including disagreements and unavailable comparisons. JSON includes `qualityAssessed: false`, `observations`, `candidates`, `probes`, `shape`, `web`, `comparison`, and `effects`. Wrapper success has `status: observed`. Each observation has `check`, `state` (`MATCH`, `DIFFERS`, `NOT_CHECKED`), `declared`, `observed`, `sources`, and `reason`. Unknown is never agreement. There is no aggregate pass/fail verdict. Unreadable/invalid project configuration is `INVALID_CONFIG`, exit 1, not an empty success. Invalid root/arguments and unavailable bundled resources retain existing toolkit error semantics. Wrapper errors are `status: not_assessed`, `qualityAssessed: false`.

Default execution performs static reads only. `--probe` is an explicit request to start at most one selected Godot or Unity version process; the caller must already have authorization for that process. It does not itself grant permission. A configured executable can have side effects even with a version argument. Processes are shell-free, time-limited, and use the existing bounded-output process runner. Actual executable, argv, provenance, stdout, stderr, exit code and signal are retained, including failures/timeouts. Nonzero exit, invalid version output, unavailable executable, or target ambiguity remain `NOT_CHECKED`. Unreal and Web never start an editor or package manager here, even with `--probe`. No build/test command is executed.

## Full source mapping

| Source observation | Portable behavior |
| --- | --- |
| Missing project/engine | Missing `project.yaml`, missing/unsupported engine: explicit `engine: NOT_CHECKED`; malformed YAML is a diagnosed input error. |
| 1: VERSION installed-at-pin-time record | Read `docs/engine-reference/<engine>/VERSION.md`. Missing/empty row is `DIFFERS`; `NOT DETERMINED` or `PER PROJECT` is `NOT_CHECKED`; duplicate rows are ambiguous. Present text is `MATCH` only for the existence of the historical record, not a current engine match. |
| 2: declared vs reference | Read a unique Engine Version row; Web can use its template `vite` row: ordinary two-column records retain their contract, and the source five-column Package/Pinned/Published/First release of this major/Node table is read only in the direct Pinned versions section. The Pinned cell supplies the version, never a release-date, historical-major or Node-range cell. Compare a determinate literal release's major.minor, with Unity 6000.N mapped to 6.N. References may add the known engine label and Unity LTS designation; historical sentences, unresolved choices and ranges are not pins. Missing/indeterminate values stay unknown. Non-Vite projects do not compare their bundler version to the Vite template pin. |
| 3: declared vs installed Godot | Consider literal editor target in the current-platform `commands.test` and `engine.path`, preserving both sources. Different targets cause `NOT_CHECKED` without probing either. A stale explicit target never falls through to another installed version. Only absence of explicit targets permits PATH `godot`. `--probe` runs selected executable with `--version`. |
| 3: declared vs installed Unity | Same explicit conflict handling; require actual editor path/name, not bare `Unity` CLI on PATH. With no explicit target, inspect the exact declared-version Hub editor location for the current OS. `--probe` runs that editor with `-version`; no guessed newest installed version. |
| 3: declared vs installed Unreal | Never run the editor. Locate explicit engine root or editor path; otherwise inspect one root `.uproject` numeric EngineAssociation launcher location, or PATH UnrealEditor-Cmd when no launcher candidate can be derived. GUID associations do not invent a launcher path. Multiple project files are ambiguous. An unavailable derived launcher candidate does not silently fall through to another PATH version. Read bounded `Engine/Build/Build.version`, requiring nonnegative integer MajorVersion/MinorVersion and optional PatchVersion. Root/editor normalization uses the last `/Engine/` segment. |
| 3: declared vs installed Web | Reuse `detectWeb` and retain its full structured result, diagnostics and provenance. Its selected project bundler determines the package to inspect. Only exact installed `node_modules/<bundler>/package.json` evidence is an installed version; a dependency range, an exact declaration without an install, or a no-bundler project does not establish installation. Null declared version stays unknown, never fake-pinned. |
| 4: Godot renderer | Compare declared Compatibility/Forward+/Mobile aliases with a unique explicit `[rendering] renderer/rendering_method` in project.godot. Missing/default/unmapped/duplicate settings stay unknown. |
| 5: Godot physics and shape | Use existing engine/layout resolution, including custom code root. Scan `.gd` extends and `.tscn` node-type declarations for 2D/3D classes. Complete scan with observed 2D-only declarations and Jolt is a disagreement. Otherwise compare a unique explicit physics backend for the declared dimension; no 2D evidence is not by itself a Jolt match. Mixed 2D/3D does not automatically contradict a 3D backend. Missing/default backend, unknown dimension, incomplete scan, or missing project file stays unknown. |
| 6: export references | Parse a literal `--export-debug`, `--export-release` or `--export-pack` target and compare its actual preset name in export_presets.cfg. Missing file/name is `DIFFERS`; duplicate names are ambiguous. File presence alone no longer masks an absent preset. No export is run. |
| 6: test runner references | Observe each distinct literal `.gd`, `.cs`, `.py`, `.sh` runner token in the configured current-platform test command. Strip `res://` and `./`; support quoted spaces; check project-contained file existence. Preserve the gdUnit4 separate-install hint. This is not test execution or coverage. Unsupported shell expressions/wrappers are not evaluated. |
| Summary/caller | Text provides checked/differs/not-checked counts and “Observations only”. Caller reports every difference, distinguishes expected uninstalled gdUnit4 handoff, and reports each unavailable check; the helper neither edits commands to hide failures nor decides readiness. |

Rendering/physics project-file comparisons remain Godot-only, as in the source; other engines receive explicit `project-file: NOT_CHECKED`. Their VERSION and installed-version observations are retained. This does not implement Unity/Unreal rendering conformance or Web browser acceptance.

## Intentional corrections and boundaries

- Parse real YAML through the existing parser, including quoted values and current-platform command maps. Do not retain the original two-level AWK limitations or use engine-table example commands as if the project declared them.
- Major.minor coherence is deliberately different from `engine verify` exact Godot import acceptance. A series match neither proves exact patch identity nor a successful import. Version ranges, unresolved choices and historical descriptions remain unknown; extracting the first number from such text does not establish a pin.
- Preserve explicit target provenance; report disagreement rather than silently probing two editors or selecting an alternate version after a failed explicit/derived selection. Bare Unity CLI is not the editor. Root-relative configured paths use project safety checks; absolute explicitly configured editor/root paths may refer to an installed engine outside the game. There is no tilde expansion or shell evaluation. Cross-host Windows paths on POSIX are unresolved.
- Project metadata uses `safePath`, regular files, no terminal symlink following, strict UTF-8 and a 1 MiB per-file bound. Source traversal avoids symlinks, hidden/framework/build/test/dependency directories and is limited to depth 32, 20000 entries and 16 MiB source content; exceeded bounds are recorded as incomplete. Root `.uproject` discovery is bounded at 20000 entries. Existing trusted bundled engine-table/layout and command-resolution readers are reused; this is not a global rewrite of those readers. Ordinary concurrent filesystem changes are not a filesystem transaction.
- Unreal installed metadata may be outside the game only under the selected declared/discovered engine root; internal path links are rejected by `safePath`. External/escaping runner scripts are unknown rather than silently read outside the game. Probe executable symlinks resolve to an actual target and that canonical path is recorded.
- VERSION table visibility reuses the existing md-section parser, including fence marker/width and HTML-comment boundaries; code examples cannot create pin records. Malformed quoted renderer/backend/preset values remain explicit unknown entries, so dropping a damaged duplicate cannot create a unique match. Blank command strings are unconfigured, never a request for engine-table examples.
- Command inspection recognizes only literal tokens and concatenated quoted chunks, not a full shell language. Operators/expansion or malformed quoting yield no speculative editor/runner selection. No shell executes configured text. This does not certify command syntax or runnable builds.
- Shape is lexical declaration evidence, not semantic class resolution or a running scene graph. Custom inherited classes, generated nodes and actual active scene dimensions need caller/engine review; `complete` means traversal completed within its bounds, not game-wide semantic coverage. Physics MATCH only compares the explicit declared dimension's backend.
- This helper does not edit VERSION.md, project.yaml, AGENTS.md, presets, dependencies, or any game file. AGENTS engine-reference wiring belongs to the setup workflow and is not silently substituted for source Claude imports here.

## Behavioral evidence plan and current limits

`toolkit/test/project-coherence.test.mjs` exercises JSON/text wrapper contracts, all four engines, explicit/no process behavior, real shell-free version argv with synthetic executables, conflict/stale/no-fallback, Unity CLI separation, Unreal readonly metadata/optional patch/malformed/link cases, Web detector ranges/install distinction, custom/mixed/unknown Godot shape and explicit backend, actual export preset/runner names, quoted paths, platform commands, YAML/size/link failures, and input preservation.

Actual Bash source comparisons use the retained original script, both an ordinary installed-series/renderer observation and the intentionally corrected hardcoded-src physics false MATCH. They are semantic comparisons, not a claim of byte-identical output. POSIX synthetic executable/Bash tests are explicitly skipped on Windows; the remaining portable tests still run. No skipped test is a pass.

Isolated macOS Node 24/26 test logs and separately retained five-fixture Bash/Codex raw outputs accompany this candidate. Synthetic editor stdout and Build.version are test inputs, not measurements of a real installed Unity/Unreal editor. Cross-platform CI, installed-package integration by root, actual installed-engine probes, full setup-engine native Skill acceptance, and human/game quality remain unassessed by this slice.
