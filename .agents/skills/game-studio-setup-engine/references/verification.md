modify ownership hashes or pretend an unimplemented upgrade command exists.

Installed at pin time evidence. Check the available native role's version-aware

row exists. No director gate applies to this utility workflow.

## Portable coherence observations

Resolve `studio/scripts/project-coherence.mjs`, invoke
`node <resolved-path> --project ROOT`. Default is static. Add --probe only for
an already authorized bounded Godot/Unity version probe; it is not a build/test.
The helper records actual candidates/processes/provenance and gives per-check
MATCH, DIFFERS and NOT_CHECKED; exit0 and qualityAssessed:false are observations,
not a pass verdict. If the installed helper is unavailable, say this readback
stage is pending rather than bypassing it or running the migration source.

Report every DIFFERS and resolve the contradictory artifact or settled decision
before claiming complete coherence. The expected missing gdUnit4 runner on a
new Godot project is reported with the test-setup handoff, never hidden by
changing commands.test. No other difference is waved away merely as a template
quirk. Explicit owner acceptance of a deliberate installed-version-ahead pin is
recorded as unresolved installation work, not a matching engine.

Report NOT_CHECKED reasons separately: absent/unavailable/ambiguous editor,
unknown root/dimension, missing project file, unresolved Web version or unsupported
command syntax. Non-Godot project-file rendering checks are not implemented and
must not be called agreement. Historical installed-at-pin-time existence and
major.minor reference coherence do not prove an exact current engine match.

Review actual engine import/build/unit/browser outcomes and image evidence,
including errors/skips and declined installations. Newly written config alone
cannot establish an installed framework, .NET support, successful build, runnable
main scene or visible correct game. Preserve first failures and bounded retry
history. Re-read modified files to confirm owner content survived.
