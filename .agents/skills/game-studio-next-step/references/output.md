# Brief orientation

Give one primary **→ Next up**, reason and concrete expected outcome. Secondary
opportunities stay subordinate. A stressed user needs one manageable action,
not a catalog dump or full audit.

Studio shape: `Where You Are: <phase>`; identify standard/full studio mode as
design documents/coordinated workflows for teams, long projects or someone
choosing that process; active work; **✓ Done**; **→ Next up** (required when
applicable); **~ Also available**; **Coming up after that**. Do not imply every
referenced team workflow is installed.

Minimal shape: `Minimal path — N of M stories complete`; active work; confirmed
engine/brief and completed count; one next action; at most three later Ready
stories in build order. The helper gives no completed titles, so show their count.
No phase label or gate. Before stories, describe the real make/play/brief step,
not `0 of 0` as completed work. Grown games without stories use `Minimal path —
grown game, N of M Features built`, counting `[x]`/`[ ]` only. Show studio-size
suggestions only under the minimal-reference guards.

Use `$game-studio-...` inline only for installed applicable Skills. No command?
Explain the action. Missing workflow? Preserve its outcome and name the capability
gap instead of presenting a fake executable or skipping required work. For MANUAL
steps ask whether the named work is already completed. User-reported completion
stays attributed. End with `Verdict: COMPLETE — next steps identified`; this means navigation only, never
project/story/release/gate completion. When essential observation fails, state
the limitation and make resolving it next rather than inventing progress.

## Conditional footers

- **Gate proximity, studio only:** all applicable required work complete or only
  one known required step left → suggest available gate-check when ready for the
  current→next transition. Manual/unknown/repeatable work or multiple unresolved
  steps does not establish proximity. Release has no invented next phase. Never
  execute a gate, spawn directors or change stage.
- **Confusion:** only actual stuck/lost/unsure input gets relevant available
  stage-detect (full analysis), gate-check (studio only) or start (orientation).
  Missing capabilities are marked, not presented as runnable. Ordinary “what next?”
  does not receive this block.
- **Rigor:** process overwhelm above minimal suggests lowering; a newly outgrown
  scope (about nine system GDDs, production-scale code or recorded Production
  transition at minimal) suggests reconsidering rigor. These are discussion
  signals, not automatic classification, advancement or mutation. Respect known
  prior suggestions and crossings; never repeat the same nudge in this
  conversation. Mere confusion is insufficient. Omit this if minimal's size
  suggestion was already shown.
- **Also installed (not in workflow):** actual frontmatter names absent from
  catalog commands, at most ten relevant to stage/request with descriptions.
  Append this footer whenever that set has relevant entries, including an ordinary
  “what next?” request; it is independent of confusion, rigor and gate triggers.
  A few relevant entries suffice; do not suppress the whole nonempty footer for
  brevity. Omit only when no relevant uncataloged Skills exist. Keep it secondary
  rather than competing primary recommendations. All minimal-route exclusions
  also constrain this footer; it does not make unrequested sprint close-out or
  other excluded workflows relevant. Select applicable nonexcluded entries.
